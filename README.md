# lilbuddy

A small, Vim-style terminal inbox for GitHub issues and pull requests.

Mostly slop to scratch an itch.

## Run

Requires Go 1.26+ and a terminal. Authenticate with the GitHub CLI:

```sh
gh auth login

# With Go installed
gh repo clone schmichael/lilbuddy
cd lilbuddy
go build && ./lilbuddy

# With GOBIN on PATH
go install github.com/schmichael/lilbuddy@latest
lilbuddy
```

## Keys

| Key                                          | Action                                                                  |
| -------------------------------------------- | ----------------------------------------------------------------------- |
| `j` / `↓`, `k` / `↑`                         | Move selection                                                          |
| `e`                                          | Archive locally; return after any newer update, including yours         |
| `o` / `Enter`                                | Open in your browser; return only after newer activity by someone else  |
| `m`                                          | Mute locally; never return unless undone or its state entry is removed  |
| `u`                                          | Undo the most recent archive, open, or mute for the current account     |
| `d`                                          | Toggle draft PR visibility (hidden by default)                          |
| `r`                                          | Refresh                                                                 |
| `g` / `Home`, `G` / `End`                    | First / last item                                                       |
| `Ctrl+d` / `Page Down`, `Ctrl+u` / `Page Up` | Move half a screen                                                      |
| `q` / `Ctrl+c`                               | Quit                                                                    |

Items are sorted by most recent update. Each row starts with the time since its
last update. Ages are recalculated on refresh.

Startup immediately displays the last cached inbox from the state file, then
authenticates and refreshes in the background. An old state file without an inbox
snapshot needs one successful refresh to populate its cache. Failed browser
launches or state writes keep the item in the list.

**Only local state is changed:** no API request marks GitHub notifications as
read, unsubscribes from threads, or changes an issue or PR. A transport-level
guard allows REST `GET` requests and parsed GraphQL **query** operations only;
write methods and GraphQL mutations/subscriptions are blocked before reaching
GitHub. GraphQL reads use `POST` as required by GitHub. Bots count as someone
other than you.

## What appears

lilbuddy merges and deduplicates:

- GitHub's `involves:USERNAME` search: authored, assigned, mentioned, or commented-on issues/PRs.
- PRs you reviewed and PRs requesting your review.
- Issue/PR notification threads, **including read notifications**: this covers
  subscribed/watched threads and additional interactions recorded by GitHub.
  Notifications generated by watching a repository are included too.

Only **open** issues and PRs are included, even when notification threads refer
to closed or merged items. Draft PRs are hidden by default; `d` includes them
alongside other open items and marks them `[draft]`. Press `d` again to hide them.
This toggle is local, makes no API request, and resets to hidden on startup.
By default each source is limited to its newest 300 results; the UI
warns when results are limited or a thread cannot be loaded. Increase with
`--limit 1000` (GitHub search cannot return more than 1,000 results per query).

### GitHub API limits

GitHub doesn't offer an exhaustive global endpoint for every interaction or
every individually subscribed issue. A watched thread with no available
notification and no searchable interaction may not appear. Reaction-only
interactions are not globally searchable. Search indexing can lag; GitHub's
retained notification history also limits coverage.

For opened items, lilbuddy checks timeline actors, body/comment edit authors,
inline review discussions, review edits, and committers. It does not treat a
timestamp change alone as someone else's activity. Activity with no identifiable
actor (for example some system updates, deleted users, and pushes of older
commits without an attributable event) cannot reliably wake an opened item.
GitHub provides only the **latest** edit attribution, so an external edit followed
by your own edit between refreshes may also be missed. Archive with `e` instead
if you want every timestamp change to wake an item.

## State and options

State is JSON at `$XDG_STATE_HOME/lilbuddy/state.json`, or
`~/.local/state/lilbuddy/state.json` if `XDG_STATE_HOME` is unset.
Actions are namespaced by account and keyed by GitHub item ID, so repository
renames don't undo mutes. The same JSON file caches each account's inbox (including
hidden drafts), its fetch time, and the last displayed account. The initial cache
belongs to that last account; authentication switches to the current account's
inbox if different. Triage decisions and cached removals are saved together.
The newest 1,000 triage actions across accounts are kept as persistent undo history;
older history events are dropped without changing their triage decisions. Press
`u` repeatedly to undo your account's actions in reverse order, including after a
restart. Undo restores the prior decision and cached item where applicable; the
next refresh reconciles it with GitHub. Undoing an open does not close the browser
tab. Navigation, draft visibility, and refreshes are not recorded in history.
Writes use an atomic replacement and private file
permissions. Use one running instance per state file to avoid competing writes.

```sh
./lilbuddy --state ./triage.json --refresh 2m --limit 1000
./lilbuddy --refresh 0          # manual refresh only
./lilbuddy --help
```

Use `u` to undo a recent mute or other triage decision. To unmute or reset an older
item, quit lilbuddy and remove its entry from the JSON file.
To reset everything, remove the file. Invalid state files produce an error rather
than being silently overwritten.

## Development

REST operations use [`google/go-github`](https://github.com/google/go-github).
GitHub's [client-library documentation](https://docs.github.com/en/rest/using-the-rest-api/libraries-for-the-rest-api)
lists it as the Go client, but it is third-party: GitHub does not currently
provide an official Go SDK. GraphQL activity queries also use its HTTP request
handling and the same read-only transport guard.

```sh
go test -race ./...
go vet ./...
```

Tests use a fake GitHub API and browser; they never access your account or launch
your browser. Browser opening supports macOS (`open`), Linux (`xdg-open`), and
Windows (`rundll32`).
